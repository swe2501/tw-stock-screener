# 任務：搜尋台股「話題族群」→ 產出 hot_topics.json

你是台股題材研究員。目標：找出**近幾天對台股有催化力的話題**，歸到族群，找出該族群的相關**上市／上櫃**個股，
產出結構化 JSON 後呼叫上傳腳本。**盤中每小時跑一次。**

## 步驟
1. **網搜**近 **7 天**的台股相關新聞、題材、催化事件（趨勢不是一天造成，要涵蓋整週）。**要涵蓋多種類別，不要清一色展覽**：
   - **財報/法說**：營收月增年增創高、財報超預期、法說展望樂觀、毛利率跳升
   - **供應鏈/訂單**：大廠追加訂單、產能滿載、拉貨潮、轉單效應
   - **漲價概念**：記憶體(DRAM/NAND)、面板、被動元件、矽晶圓、運價(貨櫃/散裝)、鋼鐵/塑化
   - **產業趨勢題材**：AI 伺服器、CoWoS/先進封裝、HBM、矽光子、機器人、低軌衛星、重電/電網、軍工、生技新藥、電動車、綠能
   - **大廠動態**：Nvidia/Apple/Tesla 新品或財報點名供應鏈、台積電資本支出
   - **政策利多**：政府補助、國防預算、晶片法案、關稅/出口管制、能源政策
   - **國際/總經**：CES/GTC/Computex 等國際展、Fed、匯率、地緣政治、油銅金價
   - **籌碼/資金面**：外資買超、投信作帳、主力連買、MSCI/FTSE 權重調整、ETF 納入剔除
   - **展覽**：近期或即將登場的產業展。可操作窗口在「開幕前布局期到展中」，heat 對展前~展中給高一點。
   **平衡規則：展覽類最多佔一半；其餘一定要有財報/訂單/漲價/題材/籌碼等非展覽話題。**
2. 把新聞歸到**族群/題材**（sector）。**sector 必須是「精簡、通用、跨天一致」的產業或題材族群名（2~5 字）**：
   - **同一族群跨天、跨則新聞必須用「完全相同」的名字**（前端靠 sector 完全比對來彙整；名字不一致會把同族群拆散、每個都變很少檔）。
   - **不要加修飾詞或事件描述**：❌「半導體與晶片設備」→✅「半導體」；❌「PCB與載板」→✅「PCB」或「載板」擇一固定；❌「AI與高效能運算」→✅「AI伺服器」。
   - **不可用事件/資金類型當 sector**：❌「財報」「法說」「展覽」「資金流」「外資買超」——這些是「催化原因」，寫進 topic／summary，不是族群。
   - **優先從這組常見族群名挑**（清單沒有的才自訂，但一樣要精簡通用）：
     半導體、IC設計、記憶體、矽晶圓、先進封裝、CoWoS、矽光子、被動元件、PCB、載板、散熱、面板、光通訊、網通、AI伺服器、電腦及週邊、電子通路、機器人、低軌衛星、重電、軍工、生技、新藥、航運、鋼鐵、塑化、化工、金融、汽車、電動車、綠能、儲能、觀光、食品、紡織、營建。
3. 對每個族群，**盡量完整**列出相關**上市／上櫃**個股（主要相關個股 **6~30 檔**，寧可多列真的相關的，不要只給 2~3 檔龍頭；真的湊不到 6 檔也不要硬塞不相關的，寧可少列）：**只能用 `scripts/tw_listed_codes.json` 裡的代號**（含上市與上櫃，`market` 欄 twse/otc），名稱以該檔為準；上櫃個股（如環球晶、群聯）也要納入，不要只列上市。不確定代號就不要放，**絕不自己編 ticker**。驗證時 codes 數量請用 6~30 的範圍（不足 6 檔的族群就不要列入，不要讓整批驗證失敗）。
   - **同一題材若近 7 天有多則不同新聞**（不同日期／來源），請**各自輸出一列**（`sector` 相同、`topic`／`summary`／`source_urls`／`published_at` 各自不同），把整週的新聞都列進去，不要一個題材只給一則。前端會依 `sector` 彙整成「該題材的相關類股（各則 codes 聯集）＋一週新聞（由新到舊）」。
4. 給每則話題一個 **heat（0~100）**：新聞量 × 新鮮度 × 是否牽涉大廠/強催化。
5. 產出 `scripts/hot_topics.json`（見下方 schema）。**只要產出這個檔就好**：
   - **不要執行任何 python、不要上傳**（上傳由排程 bat 用本機 python 執行，你的 `python` 別名會失敗）。
   - `scripts/tw_listed_codes.json` 已存在（每日排程更新），**不要重生**。

## 防幻覺鐵則（很重要）
- **每則話題必須附至少一個真實新聞 `source_urls`**（可點開的連結）。**沒有來源的話題直接不要放。**
- **codes 一律對照 `scripts/tw_listed_codes.json`**；不在清單內的代號會被上傳腳本剔除，別浪費。
- 摘要只陳述新聞講的事，**不要自行預測或給投資建議**。
- 寧缺勿濫：與其湊數，不如只給真的有料的族群（一次抓 5~15 個族群即可）。

## 輸出 schema（`scripts/hot_topics.json`，UTF-8）
```json
[
  {
    "topic": "AI 伺服器散熱升級，水冷滲透率拉高",
    "sector": "散熱",
    "summary": "輝達新平台功耗上升帶動水冷需求，多家散熱廠獲追加訂單。",
    "codes": [{"code": "3017", "name": "奇鋐"}, {"code": "3324", "name": "雙鴻"}],
    "source_urls": ["https://example-news/xxx"],
    "heat": 85,
    "published_at": "2026-08-15"
  }
]
```

## 完成後
排程 bat 會用本機 python 跑 `upload_hot_topics.py`：驗證來源、把 codes 對照上市櫃清單、**以新聞連結去重 upsert 累積、保留近 7 天**、上傳 Supabase。
你只要確保 `hot_topics.json` 格式正確、每則有來源、代號合法、且**同題材把整週多則新聞都列出**即可。**不要自己跑 python 或上傳。**
