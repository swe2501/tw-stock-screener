# 會員任務與點數兌換：2026-10-20 預覽方案

此為 UI 與規則草案，尚未啟用發點、扣點或儲值，不套用共用資料庫。

## 點數建議

任務點不對應現金。基準 100 任務點＝觀察券 1 天。首版兌換以 3 天券提供：自選一項 180、觀察 300、研究 600、進階 1200、VIP 2400。這是可調整的營運提案，不是已公告兌換率。一般免費功能不因新制度改鎖。

每日任務最多 30 點；每週任務最多 150 點。初見與里程碑每帳號一次。有效邀請第一位給 60 點的提案與既有每三人使用券分開核算；若同一任務已發使用券，不額外隱性疊發點數。每日連續登入、停留時間、重複點擊、真實買賣或交易金額都不作發獎依據。

25 個提案分初見啟程（6）、每日觀察（5）、每週精進（5）、研究里程碑（5）、分享同行（4）。實際任務清單由 apps/web/assets/member-journey.js 的 tasks 定義呈現。獎勵尚未開放；本機暱稱、筆記或已讀紀錄僅作「已有紀錄」提示，不等於伺服器核發點數。

## 會員禮遇資訊架構

- 會員總覽：身分與下一步、任務點數、待啟用券、本人邀請碼、研究足跡、禮遇捷徑。服務不可用時顯示準備中，不假填餘額；服務確實回 0 才顯示 0。
- 會員權益：一般會員功能、分級規劃、券使用說明、兌換方案與功能入口。
- 使用券／禮遇：待啟用、使用中、過期；生日禮須待活動正式發布，不因提供生日自動假發券。
- 優惠碼：活動代碼兌換；與邀請關係分開。
- 邀請好友：專屬隨機碼、有效邀請、本人唯一介紹人、補填規則。
- 任務與點數：五類任務、候選獎勵、進度／審核說明、兌換草案。
- 點數帳戶：任務點、儲值點分帳；儲值服務未開。
- 學院活動：正式已發布活動；沒有活動不虛構。

## 後端接續規格

1. task_definitions 版本化：task_id、period_type、points、verification_kind、quota、campaign/active。只有營運方可改。
2. member_task_completions：auth.uid 主體、task/version、period_key、source_document_id/revision、server_status；unique(user_id,task_id,period_key)，不靠前端勾選直接完成。
3. member_point_ledger：不可變發點／扣點／沖銷；來源事件唯一。週期上限與事件驗證在同一交易、同會員鎖中執行；API 逾時重試不重發。
4. point_exchange_definitions：券定義版本、成本、有效日期與啟停；前端只傳定義 ID／冪等請求 ID，不傳成本、天數或使用者 ID。
5. 兌換 RPC：驗證本人、餘額、活動、版本、去重，鎖同一會員帳戶；扣點與核發待啟用券在同一交易，不得出現扣點成功卻沒券。失敗全部回滾，退款用沖銷事件。
6. 券核發後一個日曆月內可啟用，啟用後完整天數。自選券只能選一項允許的 feature；VIP 與三級權限見 member-voucher-tiers.md。
7. 任務佐證保存資料識別碼、版本與必要雜湊，不把會員研究內文複製到點數 ledger。私有資料仍限制本人存取。
8. 驗收：重複完成、跨日/週界線、上限、重複邀請、撤回/沖銷、餘額不足、並行兌換、失敗重試、跨帳號讀寫及到期。正式套用與開啟活動仍須另外明確批准。
