# 會員期限與點數銜接：待套用審查

狀態：SQL 已在隔離 PostgreSQL 測試；未套用共用 Supabase，未串接金流，未啟用商品或配額。

## 本次可審查的伺服器變更

- `docs/database/member-membership-lifecycle.sql`：為人工授權增加可選到期時間；舊資料 NULL 保留原本明確的永久授權。
- 新增 `member_subscription_periods`，只供可信金流後端記錄已付款期間。會員瀏覽器不能寫入；同 provider/period ID 不得重複。
- 新增本人專用 RPC `member_membership_status()`，每次由資料庫時間核對人工授權、已付款期間、已啟用有效券，取仍有效的最高等級；全部失效即 free。
- 失效不刪除原始紀錄、不清點數、不刪筆記、自選或篩選紀錄，也不需要額外付費的排程來降級。
- 未啟用券不提前生效。訂閱關閉續訂不等於立即終止已付款期間；退款／撤銷用 revoked_at 明確處理。
- 保留 advanced 舊代碼與人工永久授權，不自動把舊會員轉成限期會員。

## 網頁／App 銜接契約

登入、回到分頁、啟用券、兌換成功、付款入帳後讀取 RPC。以 `tier` 作為會員層級、`features` 作為券的專項範圍，不能把一張指定工具券解釋為所有工具都開放。`server_time` 和 `next_change_at` 用單調時鐘計時；到點先撤除舊授權，再重新核對。切換帳號時拋棄前帳號的非同步結果，不使用 localStorage 宣稱有效的等級。

網頁未收到有效 RPC 時不能假裝開通；使用既有版本的過渡路徑必須明示仍未切換，不可宣稱全站已完成伺服器到期控制。現有 profile metadata、member_tiers 直接讀取及 share 券比較流程，須一起接到這份契約並做端到端回歸後才發布。

本次 RPC 是權益解析器，不取代其他表的 RLS。既有 `admin-member-tiers.sql` 的 VIP broker read 與 `member-vip-read-access.sql` 的 selltrack 券讀取政策，和新「不籌吃穿僅管理員」規則不一致，需另附精確政策遷移、保留 owner 存取並測試後再開放試用，不能只靠前端隱藏。

## 點數 UX 設計（沿用現有帳本）

1. 權益頁先顯示任務點數、待啟用／使用中券、券期限，並提供點數與使用券入口；不新增第二份錢包。
2. 兌換頁依伺服器商品目錄顯示所需點數、現有餘額、差額、天數及範圍；未啟用的商品保持不可兌換，不能以靜態價格按鈕假裝交易成功。
3. 兌換前一次確認；伺服器原子扣點並以固定請求 ID 防重扣。網路中斷沿用同單號查結果，不建立第二筆。
4. 明確區分「已兌換待啟用」與「使用中」。啟用前告知開始與結束時間、同時啟用會重疊，先用現有券，避免誤把新券當自動延期。
5. 到期前在原有通知中心提示，避免阻擋閱讀。無有效接續授權後回免費，資料保留；容量超額先保留讀取、匯出及刪除，限制新增必須等正式配額方案核准。
6. 不把任務點數稱為現金、不預設啟用儲值或會員 AI、不在未確認前提高商品價格或加上點數到期規則。

現行設定檔：每日研究點數上限 40、每週 200；首次任務總計 500。全方位券 1 天 500 點、7 天 2500 點，指定工具 7 天 1000 點，仍以線上啟用目錄為準。這表示新手獎勵可達一次短期體驗，日常任務則是較慢累積；原先討論的每週免費篩選次數應獨立呈現，不能讓使用者誤以為一定要先攢券才能執行免費額度。正式售價／配額尚未在此更動。

## 仍需核准與銜接

共用資料庫套用及既有授權讀取器切換須另行確認。金流仍是介面預覽；沒有已驗簽的付款事件時，不能寫入已付款期間或聲稱會自動續訂。未開啟付費服務、未推送 UAT 或正式站。
