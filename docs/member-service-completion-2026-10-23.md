## 會員驗收順序（套用 SQL 與發布後）

1. **先查帳**：點數帳戶切換三個分頁、選日期、載入較早紀錄，再匯出 CSV。匯出筆數應包含該期間所有頁；每筆時間為台灣時間。找不到資料與服務讀取失敗有不同提示。
2. **再測案件**：原回饋入口送出測試案件，在案件紀錄開啟原文，補充一段文字與一張圖片。重新整理後應能看到；另一個帳號不能讀取。客服角色回覆完成後，原會員再補充可重新開啟。
3. **測備份**：下載研究備份，再新增一筆本機資料；選回備份查看預覽，先選保留，再選合併。圖片與內容應能保留，衝突不靜默覆蓋。還原前救援檔可下載；自行修改備份內容應被校驗阻擋。用非正式重要資料驗收。
4. **測匯出**：完整帳號 JSON 應有 manifest，每區列筆數；附件及可取得截圖包含原始資料。若任一區失敗，下載內容與畫面都必須提示部分匯出，不能顯示完整成功。檔案不可包含 sb_token／refresh_token。
5. **測登入保護**：登入超過十分鐘後，更換已綁定手機／OAuth 應要求重新登入。只剩一個登入方式不得解除。取消重新授權後，帳號安全應有復原引導；不能因此建立另一個新帳號。
6. **最後測管理**：先明確指定網站會員 UUID 與最小權限；一般帳號不顯示入口，即使直接呼叫 RPC 也應拒絕。管理者先核對帳號才補扣任務點數，填原因／案件，重試同一回執不能再發。商品改價／停售後，舊券期限與內容不變。
