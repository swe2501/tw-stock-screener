## 根因：休息姿勢有套用，但輪廓與手位不足以在俯視角辨識

已讀 QA 的 UAT-REPORT.md 與相隔 17 秒的兩張部門 8 放大圖。原始碼以 `0b7568a1`／`4ff03007` 為準：

1. `office-workroom-model.js:83–95`（尤其 91）把 `review` 明確映射到 `review`，不是 `work`。109–119 只有同一 actor 另有 running／alert 時才提高優先序。部門 8 的「queued + review、無 running」離線重現，只有一個 review actor；queued 不產生工作 actor。
2. 同檔 132–136：review 有座位就坐下、`typing=false`、`handMotion=0`，但後靠僅 `-.22 rad`（約 12.6°），上臂 `.18`、手肘 `-.8`，也沒有左右向內收手。原單元測試只檢查較寬鬆角度／手部高度，未檢查手有沒有落在大腿的左右範圍，不能證明目視可辨識。
3. `office-architecture.js:66–82`：身體 pivot 高度 `.64`，肩膀相對 pivot 高 `.41`、左右 `±.21`，上臂與前臂各 `.23`。只有 X 軸轉動時，雙手依然在腿外側的 x=`±.21`，不是腿上方（髖 x=`±.1`）；俯視又受椅背遮擋。
4. `office-tower.js:193–208`：每幀唯一寫入 upperBody／arm／elbow 的是 202、205、206 行，直接套用 `personPose`；沒有其他動畫覆蓋 review。修正前本機 Chromium 部門 8 實際骨架值正是 `review / bodyLean=-.22 / arms=.18 / elbows=-.8 / typing=false`，與 QA 靜止但像工作的症狀一致。

限制：這是原始碼、QA 圖片與本機合成資料實際渲染的診斷；未登入 UAT 直接讀取那個真實人物的骨架，不能把本機重現說成實機驗收。
