# 方案與帳務：先選方案與購買方式

範圍：網站方案與帳務、管理員會員列表、既有 auth API 內帳務查詢；不影響 App。

流程為選擇上架方案與每月訂閱／單次購買 → 付款方式 → 同頁確認與同意規則 → 結果。免費方案不要求付款。每月訂閱僅使用信用卡；LINE Pay／超商僅供單次方案。保留原信用卡比例、上下排列與成功失敗動畫音效時序。

規則：升級付款成功後即時生效，依本期實際剩餘秒數計算價差、四捨五入到整元，到期日不變。降級下期生效，取消續訂本期仍可用，單次付款不自動轉為訂閱。每月以台北時區的原扣款日為錨，月底取當月最後一日；例如 1/31 → 2/28 → 3/31。降級不刪筆記／自選、不重置週額度。正式金流適配器仍須驗證事件、原子記帳與授權後才可實際變更會員。

後台以伺服器紀錄區分免費會員、每月訂閱、單次購買、管理員授權、使用券；資料不完整顯示待確認。既有 member_subscription_periods 只是有效期間，不直接代表每月續扣。測試合約不算正式訂閱；不信任會員自行修改的 metadata。

新增 lib/member_billing.py 的規則與 billing_status／billing_quote／billing_prepare 入口共用 api/auth，沒有增加 Function。LINE Pay 拒絕 monthly 避免誤以單次付款送出。

目前信用卡金流尚未串接：正式扣款與訂閱建立保持不可用。頁面測試面板可模擬升降級、取消、到期續扣成功／失敗；狀態僅暫存頁面、不寫正式資料庫、不發權益、不保存卡號。重新整理即清除。付款開關關閉時仍不顯示售價。

docs/database/member-recurring-billing.sql 僅準備，尚未套用雲端；service-role 專用，RLS 禁止瀏覽器直接讀寫。後續串金流時必須補上可信 webhook 簽章、金額與合約匹配、事件去重的交易式授權、取消／退款與重試實際整合，不能把本次測試模型當正式續扣引擎。

後續修正：商品卡直接提供「訂閱此方案」與「單次購買」，不重複詢問購買方式。只顯示同一後台來源的上架商品，移除 demo_only 假商品；載入失敗提供重試，下架中的已選商品會退回第一步。公開商品先顯示，不等待私人權益查詢；後台儲存／重新整理事件會更新商品清單。

「目前方案」位於方案與帳務頂部，可查看下次扣款／到期與待生效降級。在模擬環境可取消、恢復續訂與取消下期變更；降級直接確認下期變更，不經填卡或付款動畫。正式訂閱金流尚未串接，其取消操作保持不可用，不能宣稱已向金流取消。

2026-11-13 使用者另行明確批准只發布最小 prod 商品相容更新。原因：file／localhost 原本指向 prod，但舊 prod API 不支援 membership_catalog，實測回覆 email and password required。最小相容更新從最新 prod 獨立建立，加入商品清單、權益／帳務查詢與已驗證管理員的商品設定路由，沿用既有資料庫設定；公開價格與購買保持關閉，不變更 Auth／資料庫／裝置開關，不夾帶 UAT 整包功能。使用者同時明確要求本次完成內容發布 justy-layout 與 UAT 並對齊本機。

驗證：Python 29 項、Node 規則／介面 13 項；準備的 SQL 在隔離 PGlite 驗證 RLS、唯一合約與事件去重；桌機手機確認流程、上架數量 5→2、下架退回、取消恢復／下期降級及原動畫音效時序通過；整站深淺色桌機手機串接通過。API 入口仍 12/12。雲端新訂閱 SQL 仍未套用，付款仍未啟用。
