# 活動代號、單場點數與自動任務

## JUSTY已確認的新規則
一般活動可參加不同場次，每活動每帳號領一次；QR與補發代碼共用一次紀錄。技術分析論壇跨場次一生一次，保留舊forum-attend紀錄。活動建立時管理員設定1–10000點；其他活動可選同類一次限制並填2–40英數限制代號。既有管理員專用範圍、會員登入驗證及三次未到場限制保留。

## 本機實作
- clean_event保留event_kind/reward_points/once_per_member/limit_group，舊無欄位活動視為技術論壇；新建預設一般活動。已有報到紀錄不可更改活動類型與限制群組，避免重領。
- 新增任務可選人工或活動報到；活動必填存在且非測試的event_id；自動生成evt-<event>-v1任務，每活動一個固定任務identity。點數只從伺服器活動設定讀取，UI點數欄停用，不接受另一個發點金額。活動任務不可人工發放或透過一般save改型。
- QR與補發同走_grant與新service-only RPC；一般key event-attend:<event>:<user>，技術論壇沿用forum-attend:<user>。領點、報到及task_claims同一交易，避免只發點未完成任務。建立任務可從既有活動ledger回填完成狀態，不再發點。
- 修改活動點數以trigger同步任務顯示值，既有claim/ledger點數不變。會員端顯示活動任務代號與核銷自動發點說明，活動列表只對技術論壇套舊attended限制，取消一律1000的字樣。
- 503發點結果不明時保留補發代碼占用，避免已發點卻釋放代碼給另一人；需人工核對。沒有自動重設或重發。
