# 分級使用券設計（2026-10-20 討論稿）

> 後續實作已完成並經批准套用資料庫，活動仍關閉，詳見 member-rewards-db-status.md。最新人工規則：每三位驗證新會員送 VIP 7 天券；主力訊號、分點回測、神燈與冥燈三項只限管理員，任何券都不能開通。原下方單一 research_tools 原型限制已由分級 schema/RPC 取代，中間三階的確切組合仍待核定。

使用者新增需求：VIP 全開會員工具，另分三個等級及會員稱號；另有可自行選功能的券。各級功能尚待確認；使用者已確認自選券每張只選 1 項。本文件是設計方案，不是已啟用權限。

| 等級草案 | 稱號草案 | 功能組合方向 |
|---|---|---|
| 觀察 | 市場觀察員 | 指定市場觀察工具 |
| 研究 | 趨勢研究員 | 市場觀察＋選股與題材研究 |
| 進階 | 策略研究員 | 再加指定策略、回測工具 |
| VIP | 先見領航員 | 所有會員研究功能 |
| 自選 | 依所選顯示 | 從該券允許的功能清單選取，確認後固定 |

一般會員原有免費功能保留；分級不能為了顯示價差而無故把既有功能鎖起來。VIP 不寫 _isOwner、不提升資料庫角色、不改管理員白名單；需將各會員研究工具目前混用 owner 的 gate，逐項拆成 feature 授權及服務端驗證後再開放。

## 資料架構

- benefit_definitions：版本化券定義，tier、稱號、duration_days、allowed_features、selection_count、activation_months=1、核發上限與啟停。管理端唯寫。
- member_vouchers：user_id、definition_id/version、issued_at、activate_before、status、source_event_key unique、activated_at；核發當下保存定義快照，後續改券不追溯。
- member_voucher_choices：本人啟用時選擇的 feature，unique(voucher_id,feature)；由 RPC 在同一交易確認選項白名單、數量、去重後寫入，前端不能直接寫。
- member_entitlements：每個 feature 一筆授權，voucher_id 關聯；VIP 可展開當版全部會員研究 feature，避免 wildcard 同時開管理權限。新功能是否進 VIP 透過目錄版本策略另決定。
- feature_catalog：功能顯示名、route、是否屬會員研究、最低 backend permission、對應 gate；不收錄金鑰、管理操作或私有公式權限。

## 核發與啟用

1. 每個會員有隨機唯一邀請碼。受邀帳號只能補填並綁定一位介紹人；同一人重送不重複計數。
2. 任務完成後核發券，收到即在帳號券夾出現，不開始倒數。重複事件用 unique key 與交易鎖避免重發。
3. 核發時間在台北時區加一個日曆月為最晚啟用時間；月底取有效日期。截止前啟用有完整使用天數。
4. 固定等級券顯示包含功能；自選券顯示可選清單、剩餘選取數量、啟用期限、使用天數。未選足或不合允許清單不給啟用。
5. 本人明確確認後由伺服器驗證同帳號／未啟用／未過期，啟用和權益寫入同一交易；成功後更新網站 gate。
6. 重複啟用回原始結果，不能延長。多券同時啟用從各自確認時間開始，若已有相同功能授權先提示重疊，不悄悄消耗券。
7. 個人稱號由有效等級權益計算，可用最高有效級顯示；到期降回一般會員，研究紀錄仍保留。
